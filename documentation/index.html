Before you begin

System requirements

Node.js 18+

The API supports Node.js 18+. The included Vite 8 frontend build tool requires Node.js 20.19+ (or 22.12+); use Node.js 20.19+ or newer for local development and frontend builds.

MongoDB

MongoDB Atlas is recommended for deployment. A local MongoDB service also works for development.

Groq API key

Optional for local setup. Without a key, qualification uses a safe fallback and leads are still saved.

Local setup

Step-by-step installation

  1. 1

    Extract the project archive

    Unzip the downloaded package into a folder that you can access from a terminal.

  2. 2

    Configure environment files

    Copy server/.env.example to server/.env and client/.env.example to client/.env. Set MONGO_URI, a random JWT_SECRET (32+ characters), the allowed CLIENT_URL, and your optional GROQ_API_KEY. Do not publish your real environment files.

  3. 3

    Install dependencies

    npm install

    Run this command from the extracted project root.

  4. 4

    Load demo account and sample leads (optional)

    npm --workspace server run seed

    The idempotent seeder creates the demo administrator and ten sample leads. Demo login: admin@demo.com / password123. Change this password before deployment.

  5. 5

    Start the application

    npm run dev

    The API runs at http://localhost:4000 and Vite serves the client at http://localhost:5173. Open the client URL in your browser.

First administrator: Without demo seeding, the first user to register is assigned administrator privileges. Public registration closes after that first account is created. Existing email/password authentication remains available; there is no social login or email verification requirement.

Go live

Production deployment

Deploy the client and API separately or together on a VPS. Configure production secrets in your hosting provider’s environment settings, never in source control.

Vercel + Render

  1. Import the repository into Vercel; set the client root to client, build command to npm run build, and output to dist.
  2. Set VITE_API_URL to the Render API URL plus /api.
  3. Create a Render Web Service for the server; use npm install and npm run start --workspace server.
  4. Set MongoDB, Groq, JWT, CLIENT_URL, and NODE_ENV=production values in Render.

Railway

  1. Create a web service from the project repository and configure the server start command as npm run start --workspace server.
  2. Set all backend environment variables and the Railway-assigned PORT.
  3. Deploy the client on Railway or another static host with VITE_API_URL pointing to the API.
  4. Add the deployed frontend origin to CLIENT_URL or CORS_ORIGINS.

VPS

  1. Install Node.js 18+, configure a process manager such as systemd or PM2, and place the API behind HTTPS via Nginx.
  2. Build the client with npm run build --workspace client and serve client/dist as static files.
  3. Set backend secrets in the service environment and set CLIENT_URL to the public client origin.
  4. Restrict MongoDB Atlas network access to the server and monitor service logs and health checks.

For every hosting provider, allow your API hostname in MongoDB Atlas Network Access, use HTTPS, use unique long JWT secrets, and replace or remove the demo account before accepting real customer inquiries.

Help

Troubleshooting & FAQ

The browser reports a CORS error

Set backend CLIENT_URL to the exact frontend origin, including scheme and port. For multiple origins, provide a comma-separated CORS_ORIGINS. Redeploy/restart the API after changing environment values.

MongoDB cannot connect

Verify the MongoDB URI and credentials, enable the target database user, and add the deployed server’s outbound IP to the Atlas IP access list. Avoid broad network access in production.

Groq quota is unavailable

Check the API key, account quota, and provider status. Lead capture remains available: the service stores the lead with a neutral fallback score and a manual-review summary when AI qualification cannot run.

I cannot log in with the demo account

Run the seed command against the intended database. The demo password is only set when the demo account is first created; the seeder does not reset an existing password.

Can public registration stay enabled?

No. The setup flow intentionally permits the first account to become administrator, then closes public registration. Add staff from the authenticated administrator interface.

WhatsApp does not open the right conversation

Use a valid 10-digit phone number for an Indian number or an international number with a country code. The browser must allow pop-ups for the CRM origin.
